✓ EXISTS

✗ MISSING

Batch file loop only. No live VideoCapture, no frame queue, no async pipeline.
✗ MISSING
Temporal track management
No object ID, no Kalman filter, no velocity estimation between consecutive frames.
✗ MISSING
WGS84 / ENU coordinates
Camera positions are unitless local floats. No GPS anchor, no lat/lon/alt output.
✗ MISSING
Drone vs. bird classifier
Any pixel motion accumulates equally. No velocity gate, no trajectory model, no ML.
✗ MISSING
Background subtraction
Static clutter (trees, towers, clouds) contaminates the voxel grid continuously.
✗ MISSING
Lattice / CoT output
Outputs raw .bin binary. No CoT XML, no gRPC protobuf, no REST track endpoint.
03 // REQUIRED UPGRADES — prioritized

Engineering work to reach drone detection

01
WGS84 → ENU coordinate frame
Add LLA→ECEF→ENU transform. Each camera's GPS fix becomes the origin. Voxel centroids export as real lat/lon/alt. This unblocks Lattice integration entirely.
P1 CRITICAL
02
Real-time camera frame ingestion
Replace file-based loop with live OpenCV VideoCapture or RTSP stream per camera. Add a lock-free ring buffer (N frames deep) so DDA never stalls on I/O. Target ≥ 10 fps per camera.
P1 CRITICAL
03
Kalman multi-target track manager
Cluster voxel grid activations into blobs each frame. Feed blob centroids into a Kalman filter (or JPDA for overlapping tracks). Assign persistent track_id, estimate 3D velocity + heading. Require ≥3 consecutive hits before emitting a confirmed track.
P1 CRITICAL
04
Fix attenuation + background model
Fix the broken alpha attenuation to scale by 1/r² and apparent angular size. Add a running median background stack (updated every N seconds) and subtract it from each frame to remove static clutter.
P2 HIGH
05
Sparse voxel grid + time decay
Current 500³ grid = ~500 MB float32 — too large for real-time. Switch to a sparse hash map of occupied cells. Apply per-cell time decay: v[t] = 0.85·v[t-1] + new_hits. Evict cells below threshold.
P2 HIGH
06
Drone classification heuristics
Post-track filters: velocity band 2–30 m/s, altitude ceiling 400m AGL, hover-detection (near-zero velocity bursts), aspect-ratio of voxel blob. Flag birds with a biological trajectory model. Optionally add a CNN classifier on the motion crop.
P2 HIGH
07
CoT / Lattice Entity track emitter
Serialize confirmed tracks as CoT XML (type a-f-A-M-F-Q) for ATAK/TAK Server, or as Lattice Entity protobuf with entity_type=UAS, lat/lon/alt, velocity, timestamp. Publish over UDP/4999 multicast or gRPC to Lattice ingestion endpoint.
P3 MEDIUM
08
IR / thermal camera fusion
Add FLIR/thermal stream alongside EO cameras. Thermal signal is stronger for drone heat plumes at night. Project IR changed pixels through the same DDA pipeline into the shared voxel grid. No architecture change needed — just a new camera stream.
P3 MEDIUM

⚠ Coordinate system is the critical path. Everything downstream — classification, Lattice output, map display — depends on having camera_position in WGS84/ENU first. Without it, detected tracks have no real-world location and cannot be fused into Lattice's common operational picture.
05 // LATTICE INTEGRATION PROTOCOL

How confirmed tracks flow into Anduril Lattice

01
Voxel cluster → track candidate (3-frame minimum)
After DDA accumulation, run a 3D connected-component labeler on the voxel grid to find dense blobs. A blob becomes a "track candidate" only after its centroid appears in ≥3 consecutive frames with consistent heading. Eliminates single-frame noise, crossing birds, and reflections.
02
Centroid → WGS84 via ENU→ECEF→LLA
ENU centroid (east, north, up) + sensor origin (lat₀, lon₀, alt₀) → ECEF → LLA. This lat/lon/alt is what populates the Lattice entity position field. Use pyproj or GeographicLib for the transform.
03
Emit as CoT XML or Lattice Entity protobuf
For ATAK / TAK Server: use CoT type a-f-A-M-F-Q (friendly unmanned aerial). For native Lattice: use the Lattice Entity protobuf with entity_type=UAS, location, velocity, timestamp. Publish over UDP/4999 multicast or gRPC stream to the Lattice ingestion endpoint.
04
Update or expire track
Each new detection updates the Lattice entity position + velocity. If no detection for N frames (configurable, ~5s), emit a stale flag. After a configurable timeout, emit a delete event so Lattice removes the icon from the COP (common operational picture).
05
Angular Map UI — live track display
The Angular frontend in this repo subscribes to a Django WebSocket endpoint that mirrors the Lattice/CoT track feed. Renders drone positions on Leaflet or CesiumJS with trail history, velocity vector arrows, altitude AGL, classification confidence, and threat level coloring.
